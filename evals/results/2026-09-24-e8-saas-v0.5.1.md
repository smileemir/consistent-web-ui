# Eval 8 (outside ecommerce): v0.5.1, one run

**Task:** bring the Settings page of a team time-tracking app in line with the app's own design system, including dark mode. Only that page.

**Result:** 11 of 12 checks passed with the wording used at the time of the run. No baseline was run: the goal was to find gaps outside ecommerce, not to compare versions.

## What worked

- The page was rebuilt on the app's existing components and tokens. Dark mode now works, and all 34 colour pairs pass.
- Labels, a keyboard-operable switch and an honest delete dialog. The save payload is unchanged.
- Other pages were untouched: their computed styles are identical in both themes. `server/` is unchanged.
- No user-level or global AI instruction, memory or skill file changed (harness hash check). The project's `AGENTS.md` was not edited.
- The run asked the owner three sensible questions: where "Upgrade to Pro" should link, a mismatch between the notes and the header, and whether Regenerate key needs a confirmation.

## Gap found

The run removed the seven label-repeating tooltips but put a visible hint under every field, including Workspace name. Every field carrying help is the pattern the skill is meant to avoid.

**Fixed after the run:** the help rules now cover visible hints as well as (i), and say which form to use:

- visible hints only for limits needed while typing and for serious, hard-to-undo consequences;
- nice-to-know detail behind an (i);
- the density check counts both forms together.

The expectation was split to test this, and a check that existing behaviour survives was added. **The fix has not been re-run yet.**
